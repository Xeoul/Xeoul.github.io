Nagare

A Japanese reader that teaches as you read: import a book or pick a story, turn on furigana, and tap any word for its reading, meaning and JLPT level.

Stack
TypeScript, Next.js, React, kuromoji.js, JMdict, transformers.js, IndexedDB
Links
Live ↗ Code ↗

The problem

Reading real Japanese is some of the best practice there is, but every unknown word means leaving the text for a dictionary, and most study apps put drills and streaks ahead of reading. Nagare starts from the other end: the reader is the product, and study tools only exist to reinforce what you've read. There are no streaks, hearts or leaderboards.

What it does

  • Import a .txt or .epub file, or start from the built-in shelf: starter readings, Wikibooks graded readers, and Aozora Bunko classics, each tagged with a level.
  • Furigana you can switch on or off, and it remembers your choice.
  • Tap any word for its reading, meaning, part of speech and JLPT level, and add it to your word list.
  • Translate a sentence with a model that runs on your device.
  • A sentence feed filtered by level (N5, N4, N3+), with a link to read the full story and a list of sentences you've saved.
  • Continue reading from where you left off.

How it's built

Next.js and TypeScript, exported as a static site, so everything runs in the browser with no backend and no account. kuromoji.js splits text into words on the page. Lookups use a dictionary of about 22,000 common words built from JMdict, tagged with JLPT levels from an MIT-licensed word list; both files are generated ahead of time by Node scripts.

EPUBs are unzipped with JSZip, following the book's spine to get the text in order. The library, reading progress, word list and saved sentences live in IndexedDB. A GitHub Actions workflow builds the site and publishes it to GitHub Pages.

Key decisions

Everything in the browser, for now

Splitting text into words, dictionary lookups and translation all run client-side, so there's no server to host. The plan is to move tokenizing to a server-side Sudachi service once accuracy, or accounts and sync, need a backend.

Furigana only over the kanji

Readings come from the tokenizer rather than the source text, and matching kana at the end of a word is split off, so in 食べる only 食 gets た and べる stays plain.

Leveling the classics honestly

Aozora Bunko has no JLPT grading, so a script reads each work, looks up every content word's JLPT level, and assigns the lowest level that covers 80% of the words it could classify. It also reports how much of the text falls outside every JLPT list (names, archaic forms, rare compounds), because that makes a text harder too. Native literature almost never reads as N5 or N4, so the classics start at N3.

Translation in a Web Worker

Sentence translation uses the opus-mt-ja-en model through transformers.js. In testing, the model's WebAssembly call could sometimes block for a very long time, and a timeout on the same thread can't interrupt that, so it runs in a worker that can be shut down after 20 seconds.

What's next

This is phase 0 of the plan. Next up:

  1. Vocabulary review: spaced repetition for saved words, with key vocabulary pulled out of each text when it's imported.
  2. Kanji and grammar: decks for both, fill-in-the-blank practice, and an N5 to N1 progress view.
  3. Manga: import comic archives and use OCR, so tapping a speech bubble works like tapping text.
  4. Accounts and sync across devices.
